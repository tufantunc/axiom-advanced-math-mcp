# S3358 — flatten nested ternaries

Date: 2026-09-02
Branch: `fix/sonar-s3358` (from `main` c824aec)
Rule: `typescript:S3358` — ternary operators should not be nested (17 sites,
12 files).

## Problem

Nested ternaries force the reader to reconstruct an if/else tree in their
head, and this repo's worst defect class (wrong verdicts, wrong signs) hides
exactly in misread condition trees. Seventeen sites, four shapes:

1. **Verdict/explanation triples** — `evaluated ? (verified ? A : B) : C` in
   verify/index.ts:467,507,533; an error-message tree in calculus.ts:320; a
   template-nested imaginary term in fourier-transform.ts:63.
2. **Value-mapping chains** — commands.ts:71 (output format),
   output-cleanup.ts:201 (complex coefficient), sequence-utils.ts:139 (n²
   term), linear-regression.ts:47 (sign, with the negative-first-term
   subtlety) and :50 (varStr), extractors.ts:1015 (line1), exact-value.ts:46
   (the precision display ternary).
3. **Callback selection** — calculus.ts:179 (verify callback chosen by
   integral/system/…).
4. **A duplicated chain** — hypothesis-testing.ts:145 and :211 repeat the
   same `two_sided/less/greater → ≠/</>` mapping.

## Design

All conversions are behavior-identical rewrites:

- Shapes 1–3 become `const` bindings built by if/else statements immediately
  before their use (or `let` + assignment for the callback selection).
- Shape 4 becomes one shared helper `altSymbol(alternative)` in
  hypothesis-testing.ts — the Sonar fix and a DRY fix together.
- http-app.ts:255 (the portability boundary) converts to a plain if/else
  with no new imports; `test/http-portability.test.ts` continues to enforce
  the boundary.

Keepers (probed semantics that must not move): the verify verdict strings
`TRUE ✓` / `FALSE ✗` / `UNKNOWN — could not be checked` (exit codes derive
from them), the negative-first-term sign `c < 0 ? '-' : ''`, the complex
coefficient mapping ('' and '+' → 1, '-' → −1), and exact-value's
precision/no-precision display choice.

One commit — a single-kind mechanical change — then review-pro with the
correctness reviewer first and the mutation tests reviewer last and alone.
