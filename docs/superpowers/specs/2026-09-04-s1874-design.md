# S1874 — migrate the deprecated server.tool/prompt registrations

Date: 2026-09-04
Branch: `fix/sonar-s1874` (from `main` d365eca)

## Problem

Ten registrations use the SDK's deprecated `server.tool(name, description,
paramsSchema, cb)` / `server.prompt(name, description, argsSchema, cb)`
overloads: two tools in src/server/index.ts (compute, verify), seven prompts
in src/server/prompts/index.ts, and the plot tool in
src/server/tools/plot/index.ts. SDK 1.25.3 marks them
`@deprecated Use registerTool/registerPrompt instead`.

## Design

Pure mechanical migration to the config-object overloads (verified against
the SDK's own type declarations):

- `registerTool(name, { description, inputSchema }, cb)` — name and callback
  byte-identical; description and schema move into the config object.
- `registerPrompt(name, { description, argsSchema }, cb)` — same shape.

No behavior change: the new overloads produce the same tools/list and
prompts/list output (name, description, inputSchema/argsSchema). `title`,
`outputSchema`, `annotations` and `_meta` stay unused (YAGNI — nothing in
the repo needs them and adding them would change the advertised surface).

## Verification

The integration suite exercises the real MCP transport: tools/list is
queried and all three tools called (74 tests); http-contract.test.ts pins
prompts/list. Five gates, then review-pro with the correctness reviewer
first (old/new tools/list JSON comparison) and the mutation tests reviewer
last. One commit, three files.
