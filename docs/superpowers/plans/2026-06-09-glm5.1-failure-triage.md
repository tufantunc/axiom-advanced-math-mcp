# GLM-5.1 Failure Triage — Execution Plan

Execute INLINE (superpowers:executing-plans style): the controller dispatches two analysis subagents, then synthesizes the findings doc. **Goal:** Bucket GLM-5.1's tool-augmented failures (CAS-quick + olympiad-quick) into tool-loss / capable-but-erring / incapable, cross-reference tool-addressable failures against shipped Tier 1/2/3, and write an evidence-based "what to build next" recommendation.

## Task 1: Triage CAS-quick failures (analysis subagent)

**Files:** none written by the subagent; it returns structured JSON to the controller.

- [ ] **Step 1: Dispatch the CAS analysis subagent** with this prompt:

```
You are triaging benchmark failures (READ-ONLY analysis — do not modify any files).

Read the trace file at:
/Users/tufantunc/Desktop/Projects/Personal/axiom-advanced-math-mcp/benchmark/results/2026-05-08-08-42-51-zai-cas-quick-details.jsonl

It is JSONL (one JSON object per line, 60 lines). Each record:
{ question, groundTruth, baseline, toolAugmented{ extractedAnswer, correct, method, toolCalls[{name,args,result}] } }

Consider ONLY records where toolAugmented.correct === false (there are 19). For EACH such failure, read the question, groundTruth, the toolCalls (name/args/result), and toolAugmented.extractedAnswer, and classify it into EXACTLY ONE bucket:

- "tool-loss": Giac produced (or trivially could have) the correct answer but it was lost in plumbing/extraction. Signals: a tool `result` contains the groundTruth (or a normalized-equal form) while extractedAnswer ≠ GT; output corruption ("micro", truncated LaTeX, "list[...]", stray quotes, set notation that should have matched).
- "capable-but-erring": the model engaged with a reasonable formalization but hit a recoverable error a retry/escalation could fix. Signals: GIAC_ERROR/undef/syntax error in a result then giving up; correct intent but wrong method/domain (real solve where complex roots were needed); correct tool output but a wrong final answer from a downstream slip.
- "incapable": neither model nor Giac can reach it with the current stack. Signals: misformalization (tool args don't match the problem); Giac genuinely can't (geometry construction, proof/existence); GT is a proof/long-text/symbolic-in-n answer.

Also, for tool-loss (and any capable-but-erring with an obvious tooling fix), tag tierFix with which SHIPPED tier now addresses it, else null:
- "T1" output hygiene: series order_size/truncation, stray latex quotes, list[...]→set, boxed fail-safe.
- "T2" self-verification: real→complex solve escalation (complex-only roots), verified signal.
- "T3" input normalization: unicode glyph corruption (x²→xmicro, middot ·).

Set noToolCall=true if toolCalls is empty.

Return ONLY a JSON array (no prose) of objects with this exact shape, one per failure:
{ "index": <number>, "question": "<short>", "gt": "<groundTruth>", "extracted": "<extractedAnswer>", "bucket": "<one of the three>", "tierFix": "T1|T2|T3|null", "noToolCall": <bool>, "evidence": "<the exact tool result snippet / extracted / GT that justifies it>", "reason": "<one line>" }

Quote real evidence from the trace for each — do not invent. If a case is genuinely borderline, pick the best bucket and say "borderline: ..." in reason.
```

- [ ] **Step 2: Validate the subagent output.** Confirm it returned ~19 objects, each with a bucket and quoted evidence. Spot-check 3 classifications against the raw trace (grep the index in the JSONL) to confirm the evidence is real. If evidence is missing/fabricated or the count is far off, re-dispatch with corrections.

- [ ] **Step 3: Record the CAS result** (hold in controller context for synthesis in Task 3).
