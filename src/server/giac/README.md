# Giac WASM Integration

This directory contains the Giac Computer Algebra System (WebAssembly) integration for the Axiom MCP server.

## How it works

The project uses a WASM build of [GeoGebra/giac](https://github.com/geogebra/giac), providing:

- Full Giac/Xcas symbolic computation (integrals, derivatives, limits, equation solving, etc.)
- Platform-independent — runs anywhere Node.js runs
- Lazy initialization — WASM loads on first `evaluate()` call

## Building giac.wasm.js

```bash
npm run build:giac:wasm
```

This runs a Docker-based build that compiles giac C++ to WebAssembly via Emscripten. Output: `giac.wasm.js` (~6.5MB, WASM binary embedded as base64).

Requirements: Docker Desktop running.

## Files

- `interface.ts` — GiacEngine interface
- `wasm-wrapper.ts` — WASM engine implementation (loads giac.wasm.js, binds `_caseval`)
- `worker-host.ts` — Forks and supervises the worker: per-call timeouts, recycle on crash
- `worker.ts` — The forked child; runs the synchronous WASM engine off the main thread
- `wrapper.ts` — Lazy-initializing engine singleton over the worker host
- `session-lock.ts` — Serialises whole tool calls and resets the engine at the boundary,
  so one caller's `sto`/`assume` cannot leak into the next
- `cache.ts` — Memoized `evaluate()` results, keyed on the Giac expression string.
  Giac-domain state, so it lives with the engine. Note the clearing is owned one
  layer up: `src/server/tools.ts` clears it at the same tool-call boundary where
  `session-lock.ts` resets the engine, because the cache is a second state-leak
  channel that the reset alone cannot close.
- `health-probe.ts` — Readiness check used by the HTTP `/health` route
- `index.ts` — Barrel export
- `giac.wasm.js` — Compiled WASM module (generated by build)
- `giac.wasm.d.ts`, `wasm-types.d.ts`, `giac.d.ts` — Type declarations
